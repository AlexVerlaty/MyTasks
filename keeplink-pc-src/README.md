# MyTasks · вход в Keep — программа для Windows

Крошечная программа с одной задачей: подключить Google Keep к боту **MyTasks** с
компьютера, не открывая «инструменты разработчика».

Windows-близнец андроидного приложения (`site/keeplink-src`). Тот же протокол, та же
пара гугловских адресов, тот же результат — отличается только оболочка.

## Почему программа, а не ссылка

У Google Keep нет публичного API. Единственный ключ — кука `oauth_token` из твоей же
сессии входа, а она `HttpOnly`: страница на JavaScript её не прочитает **никогда**, и это
не наша недоработка, а её назначение. Прочитать её может нативная программа, которая сама
держит браузерное окно.

Именно поэтому альтернативой была инструкция «нажми F12 → Application → Cookies». По
логу: семь начатых подключений, одно доведённое до конца.

**Замерено 15.08.2026** (`.planning/phases/29-keep-alternatives/RESEARCH.md §0.0.1`):
`CoreWebView2.CookieManager.GetCookiesAsync` отдаёт куки с флагом `HttpOnly` — и свою
подставную, и живые `NID`/`__Host-GAPS` с `accounts.google.com`. До замера это было
допущением из документации, и план стоял на воротах, пока оно им и оставалось.

## Что она делает

1. Показывает страницу входа Google (`accounts.google.com/EmbeddedSetup`) внутри себя.
2. Ты входишь в свой аккаунт — **пароль вводится только на странице Google**.
3. Программа читает из своей же сессии одноразовую строчку `oauth_token` и меняет её у
   Google на постоянный ключ (`aas_et/…`).
4. Показывает ключ с кнопкой «Скопировать». Ты отправляешь его боту в личный чат.

Обмен делается на месте, как в андроидной версии. Иначе вернулось бы окно на время и
обмен на стороне бота, который может не удаться, — ровно то давление, ради снятия
которого всё и затевалось.

## Границы, честно

- **Две сетевые точки, обе Google** и никаких других: `accounts.google.com/EmbeddedSetup`
  и `android.clients.google.com/auth`. Проверить — `Protocol.cs`, константы вверху.
- **Ключ никуда не отправляется программой**: показывается на экране и по твоему нажатию
  кладётся в буфер обмена. На диск не пишется, в лог не пишется, аналитики нет.
- **Ключ `aas_et/…` постоянный и открывает весь Google-аккаунт.** Так устроен Keep.
  Отправляй только боту MyTasks. Отозвать — `/unlinkkeep` или
  `myaccount.google.com/permissions`.
- **Программа не подписана.** Windows покажет синее окно «Защита Windows». Подпись стоит
  денег и юрлица, которого у семьи нет; поэтому окно названо в тексте шага заранее, а не
  оставлено пугать человека молча.
- Профиль WebView2 создаётся заново на каждую попытку и лежит во временной папке: иначе
  просроченная кука с прошлого раза подхватилась бы мгновенно и сорвала попытку.

## Сборка

Нужны .NET 8 SDK и Windows. WebView2 Runtime на Win10/11 уже стоит.

```
dotnet publish -c Release
```

На выходе один файл `bin/Release/net8.0-windows/win-x64/publish/MyTasksKeepLink.exe`,
~1,3 МБ. Иконка и логотип вшиты внутрь (`EmbeddedResource`), поэтому это действительно
один файл, а не «скачай ещё папку рядом».

## Состояние

**Не выпущено.** `link_flow.DESKTOP_APP_READY` стоит в `False`, поэтому бот пока никого
сюда не отправляет и компьютерный путь работает по-старому. Переключатель поднимают одним
коммитом вместе с публикацией `.exe` на странице — раньше нельзя: флоу, зовущий на
несуществующую страницу, это ровно та уверенная неправда, которую этот проект и вычищает.
